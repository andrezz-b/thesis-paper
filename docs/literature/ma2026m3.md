# M$^3$-VQA: A Benchmark for Multimodal, Multi-Entity, Multi-Hop Visual Question Answering

## TL;DR

Knowledge-based VQA benchmark (13,125 image-question-answer triples) where one image can show several fine-grained entities and questions need parallel or sequential multi-hop reasoning over Wikipedia pages. Entities are linked to Wikidata QIDs, and answers are built from Wikidata via SPARQL, but the released gold is Wikipedia evidence: the released data contain no SPARQL and no Wikidata IDs (checked in the repo and on Hugging Face, 2026-11-07). Closest thing to our design: a controlled multimodal knowledge base with hard-negative entities, an oracle setting, and a planner/executor agent with detection and image retrieval tools.

## Problem and contribution

- Problem: existing knowledge-based VQA sets (OK-VQA, S3VQA, ViQuAE, KVQA, EVQA, InfoSeek, Dyn-VQA) mostly have one main entity and one or two reasoning steps (§1, §2, Table 1).
- Contribution: M$^3$-VQA with multi-entity questions, sequential and parallel multi-hop reasoning, gold evidence per hop, and a curated multimodal knowledge base (§1). Difficulty has two axes: entity complexity (number of visual plus textual entities) and hop complexity (nodes in the reference evidence chain) (§3).
- Evaluates 16 MLLMs in three settings: Original (image + question), Oracle (gold evidence), KB (retrieval) (§5.1).

## Method

- Task: $f:(I,Q,K)\to A$ with an external Wikipedia KB $K$ and a reference evidence chain $E$ (§3).
- Image and entity annotation: images come from existing fine-grained datasets that already label entities (CelebTo, FGVD, FlickrLogos-47, LogosInTheWild, Menu-match, Oktoberfest, UEC-FoodPix, UNIMIB2016), plus single-entity images from EVQA and InfoSeek extended to multi-hop, plus manually collected web images (§4.1, App. D.1).
- Entity linking: label strings are matched to Wikidata QIDs with QLever on the 22 Aug 2022 dump; unique match accepted, ambiguous ones resolved manually; entities without QID or English Wikipedia page excluded (App. D.2).
- Parallel questions: human-written templates per relation type with placeholders such as "person" or "brand"; answers via SPARQL on Wikidata; extra textual entities of the same category added; some questions paraphrased by LLMs (§4.1).
- Sequential questions: "bridging entities" from answers, LLM-generated follow-up questions validated against the grounding information, chained (§4.1).
- Evidence: each sub-question linked to a Wikipedia article, the answer sentence and section index annotated (§4.1).

## Data / benchmark

- Is gold SPARQL released? No. SPARQL is used during construction of parallel questions (§4.1), but the released fields are data_id, image_id, question, question_type, question_hop, entity_num, answers, answer_evals (aliases), img_entity_names (names only, no QIDs), evidence sentences, evidence URLs and section ids/titles (GitHub README, Hugging Face questions file, checked 2026-11-07).
- Is the depicted entity named in the question text? No. Questions use category placeholders ("person", "brand") for visual entities (§4.1); textual entities are named. The Entity-Name oracle setting supplies the entity name separately (§5.3).
- Which knowledge graph? Wikidata (dump of 22 Aug 2022, via QLever) for linking and answers; English Wikipedia snapshot of 13 Aug 2022 (about 2M articles) as the retrieval KB (App. D.2, D.3). The agent does not query Wikidata at evaluation time.
- Multi-hop? Yes. Hops: 1 (1,092), 2 (3,181), 3 (4,546), 4+ (4,306); entities: 1 (2,992), 2 (2,183), 3 (3,644), 4+ (4,306); average 3.1 hops, 2.8 entities (Table 2). Types: parallel and sequential; question-wording types are heuristic prefixes (App. E.3, Fig. 4).
- Image index and distractors? Yes, a KB with a text corpus (at least 3 sections per entity page, incl. the gold one) and an image corpus (first image of each entity page). It holds all M3-VQA entities plus about 5 hard negatives each: top 20 most similar entities by all-mpnet-base-v2 embeddings of Wikipedia summaries with FAISS, 5 sampled at random. Retrieval runs over the whole constructed KB, not only positives and negatives (App. D.3).
- Agentic systems evaluated? Yes: own Planner (GPT-4o) / Executor (object detection by Qwen2.5-VL-7B, text retrieval with BGE-large-en-v1.5, image retrieval with CLIP ViT-L) / Solver (tested MLLM) (§5.4, App. F.2 to F.5).
- Size, splits, licence: 13,125 triples, 10,565 unique images, 7,611 unique questions, 4,645 unique entities (Table 2). Hugging Face has a single `test` split (no dev split) and states licence MIT; the paper states no licence and says data are for non-commercial academic use (Ethical Considerations); the GitHub repo has no licence file. License plates are blurred. The controlled knowledge base is built on EVQA's (repo README).

## Key results

- Original setting: best model Qwen2.5-VL-72B 32.6%; GPT-4o 27.5% (may be lower due to refusals) (Table 3).
- Q-only average 15.6% vs Original average 24.5% (Table 4, §5.2).
- Oracle averages: Sentence 49.9, Section 45.1, Entity-Name 34.7 (Table 4). Best Sentence 58.7 (InternVL2.5-78B).
- KB setting, e.g. Qwen2.5-VL-7B: Original 22.5, Heuristic 25.7, Agentic 31.2; Qwen2.5-VL-72B: 32.6, 36.6, 38.9 (Table 5). Agentic beats heuristic for all seven models.
- Accuracy under Sentence oracle decreases monotonically with hops and entities (Fig. 2, §5.5). In the Original setting it does not, since more hops add named textual entities (§5.5).
- Partial evidence helps steadily (Table 6, §5.6).

## Limitations

Authors say (Limitations section): English only; Wikipedia-only knowledge; a few errors or ambiguous questions remain; no systematic study of reasoning strategies such as chain-of-thought.

We see (assistant reading):
- The agent is a plain Planner/Executor/Solver with GPT-4o as Planner, so agentic gains partly reflect a stronger planner than the tested solver.
- Hard negatives are chosen by text-summary similarity, not visual similarity, so they are not hard negatives for image retrieval in our sense.
- Heuristic baseline is fairly simple (whole question and whole image as queries).

## Citable claims

- Existing knowledge-based VQA datasets mostly involve one main entity and at most one or two reasoning steps (§1, §2).
- M3-VQA contains 13,125 triples with average 3.1 hops and 2.8 entities (Table 2).
- Best Original accuracy is 32.6%; with gold sentence evidence the average is 49.9% (§5.2, Table 4).
- Removing the image drops the average from 24.5% to 15.6% (§5.2, Table 4).
- Agentic retrieval (decomposition, detection, per-segment image retrieval) beats heuristic one-shot retrieval for every tested solver (Table 5, §5.4).
- Accuracy falls with more hops and more entities even with full gold evidence (§5.5, Fig. 2).
- Providing only the entity name gives a 10.2 point gain over Original, i.e. visual entity recognition is a major bottleneck (§5.3).

### Example: what entity annotation means (added at the user's request)

Example 7 (App. K): image of a bird; question "Where are this bird and Paradise shelduck native to?"; gold answer "Australia, New Zealand".
- Image entity annotation (ground truth, hidden from the model in the Original setting): *Australian wood duck*, linked to its Wikidata ID and Wikipedia page.
- Text entity: *Paradise shelduck*, named in the question.
- Gold evidence: one Wikipedia sentence per duck.
- The model gets only image and question, so it must recognise the bird first and then look up both origins. In the entity-name oracle the annotation is given to the model.

### Hard negatives as a distractor approach (added at the user's request)

- M3-VQA: about 5 hard negatives per entity; embed Wikipedia summaries (all-mpnet-base-v2), take the top 20 nearest entities with FAISS, sample 5 at random (App. D.3). Similarity is textual, not visual.
- Leaning for our index (IX-01): choose distractors that are `instance of` the same class as the target. Text-similarity neighbours as in M3-VQA could be an additional distractor source.

### Oracle versions (added at the user's request)

- Entity-name oracle: the model is also told the entity names (Example 7: "Australian wood duck, Paradise shelduck"). Recognition is removed, fact recall remains. This is the version we want to adopt (§5.3; average 34.7% vs 24.5% Original, Table 4).
- Sentence and Section oracles (gold Wikipedia sentence or section) are not planned.
- SPARQL-triples oracle (give the agent the relevant Wikidata triples, analogue of their Sentence level): conceivable, but unlikely.
